# 拆分商品库存与订单结算为独立限界上下文

Status: accepted

尽管 FlashMart 首期定位为极简限时抢购小店，仍在启动阶段即划分为自治的「商品库存上下文」与「订单结算上下文」，由商品库存作为上游（OHS/PL）提供标准化库存预占、扣减与退回能力，订单结算作为下游通过防腐层（ACL）协作，以支持未来商品库存复用到其他营销和售卖活动。

## 备选方案

- 单一核心限界上下文起步：首期把商品配额、库存预占与订单状态合并在同一上下文的强一致事务内，可省去跨上下文同步端口、防腐层映射与成单失败时的预占释放补偿；但会导致库存模型与抢购订单耦合，后续扩展其他营销/售卖活动时仍需高成本拆分。

## 影响

- 订单创建前需先向上游发起库存预占，若上游预占成功但下游创建订单失败，订单结算上下文必须负责发起补偿释放预占库存。
- 订单结算上下文需通过独立防腐层消费上游商品快照与库存原语，严禁直接引用商品库存上下文的内部领域模型或私有状态。
